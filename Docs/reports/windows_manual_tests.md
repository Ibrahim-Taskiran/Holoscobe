Limitations to observe: asynchronous Win32 success means the request was accepted, not that a hung or self-managing application completed it. `SendInput` has no atomic HWND routing; wheel/zoom require the same foreground and pointer target, but an external focus change during the native call cannot be made atomic. No attempt is made to bypass UIPI. A native COM operation already in progress cannot be forcibly cancelled; the caller's wait is bounded and expired queued writes are rejected.
